# ProfitNet — Flutter client

Android and iOS app built from one Dart 3 code base. This step contains the
shared foundation and the onboarding flow specified in
[`docs/06-flux-onboarding.md`](../docs/06-flux-onboarding.md); the project
layout follows [`docs/04-structura-proiect.md`](../docs/04-structura-proiect.md) §4.

## Layout

```
lib/
├── main.dart, bootstrap.dart       # restores the session, then runs the app
├── app/                            # MaterialApp.router, go_router + redirect, adaptive/ helpers
├── core/                           # error, network, database, security, session, location, model, design
├── features/
│   ├── onboarding/{domain,data,presentation,di}
│   └── home/{domain,data,presentation,di}   # provisional Home (greeting + logout)
└── l10n/                           # generated by gen-l10n from ../l10n/*.arb
l10n/app_ro.arb (template), app_en.arb
assets/fixtures/, assets/fonts/     # copies of ../api/fixtures and ../design/fonts
tool/sync_shared_assets.dart
test/, integration_test/
```

Layer rules (`domain` is pure Dart, `presentation` never imports `data`, no
feature-to-feature imports, `core` imports no feature) are enforced by
`test/architecture/layering_test.dart`. Material and Cupertino widgets come
from `package:material_ui` / `package:cupertino_ui` (the
`package:flutter/material.dart` library is deprecated in this SDK).

## Commands

Requires Flutter 3.50 / Dart 3.14.

```sh
flutter pub get
dart run build_runner build      # Riverpod, Freezed, json_serializable, Drift
flutter gen-l10n                 # also runs automatically on build (generate: true)
dart run tool/sync_shared_assets.dart   # after ../api/fixtures or ../design changed
flutter analyze
flutter test
```

Generated sources (`*.g.dart`, `*.freezed.dart`, `lib/l10n/`,
`lib/core/design/livada_tokens.dart`) are committed, so the project analyses
without a build step. Re-run `build_runner` after touching annotated code.
(The old `--delete-conflicting-outputs` flag no longer exists in
build_runner 2.17; conflicting outputs are overwritten by default.)

## Running without a backend (demo mode)

```sh
flutter run --dart-define=FAKE_API=true
```

The fake API (`lib/core/network/fake_api_interceptor.dart`) answers with the
files in `assets/fixtures`: any valid number gets a code, `123456` signs in,
any other code returns `OTP_INVALID`; `PATCH /me` and `PUT /me/consents` are
kept in memory. It is installed only when the flag is set **and** the build
is not a release build (`kReleaseMode` guard), so the code is tree-shaken out
of release builds.

Against a real backend: `--dart-define=API_BASE_URL=https://.../v1`
(default: the staging placeholder host).

## Tests

- `flutter test` — unit, contract (decodes every `../api/fixtures` file),
  controller, interceptor, widget and whole-app flow tests on the fake API.
- `flutter test integration_test/onboarding_flow_test.dart` — the same happy
  path on a device or emulator.

## Not done yet

- Certificate pinning is wired (`CertificatePinning`) but disabled: real
  SHA-256 pins can only be added once the production domain exists.
- `assets/fixtures` is declared as a regular asset, so the JSON files are
  packaged in release builds too (the code that serves them is not). They
  only contain placeholder data; remove the asset entry or move to flavors
  before the first store release.
- Launcher icons, splash screen, signing and Fastlane are untouched
  `flutter create` defaults.
